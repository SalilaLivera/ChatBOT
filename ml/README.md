# ml/ — Machine Learning Development

All model development happens here. Two independent tracks.

| Track | Status | Purpose |
|---|---|---|
| `fer/` | **ACTIVE — Phase 2/3** | Facial emotion recognition from camera frames |
| `sentiment/` | Later phase | Sinhala/English text mood |

The two models are developed and evaluated **independently**, then combined by the fusion
engine. Do not couple them.

## Why they stay separate

The research question is whether combining the modalities helps. That question is only
answerable if each modality has its own measured performance. Face-only, text-only and
face+text are three separate experimental conditions (Build Plan, Phase 7 and 11).

## Folder layout — identical for both tracks

```
ml/<track>/
├── README.md        Pipeline, notebook order, current status
├── notebooks/       Numbered notebooks — the actual work
├── data/
│   ├── raw/         Downloaded datasets, never edited
│   └── processed/   Preprocessed splits, generated by notebooks
├── plots/           Figures: confusion matrices, curves, Grad-CAM
├── models/          Trained weights, checkpoints, exported TFLite
└── outputs/         Metrics, run logs, per-run metadata JSON
```

Add notebooks freely. **Do not add folders per experiment.**

## Experiment tracking — notebooks record their own metadata

There is deliberately **no separate experiment-tracking infrastructure**. This was the
Gate 1A resolution: each notebook records its own run metadata to `outputs/`.

Every training or evaluation notebook writes a JSON record containing:

| Field | Why |
|---|---|
| `run_id` | Unique identifier, timestamp-based |
| `timestamp` | When it ran |
| `dataset_version` | Which processed split was used |
| `model_version` | Which model this produced |
| `hyperparameters` | Learning rate, batch size, epochs, augmentation settings |
| `random_seed` | Reproducibility |
| `metrics` | Accuracy, macro-F1, per-class precision/recall |
| `notes` | Anything unusual about the run |

This satisfies NFR-12 (reproducibility). A result without its run record is not a result.

## Rules

1. **Read `docs/system/MOOD_STATE_SPEC.md` first.** It defines the label space. The FER
   7→3 mapping is not yet decided — §B2 gives the derivation procedure, not the answer.
2. **Never invent a metric.** Report what was measured, on the stated data, with the run ID.
3. **No raw facial frames persisted** outside `data/`, and never in `outputs/` or `plots/`
   in identifiable form.
4. **Large files stay local.** Datasets and model weights are not committed.
5. **No behavioural signals.** Typing speed and response delay are not model inputs.
6. **Do not tune on the test set.** Validation drives decisions; test is touched once.

## What belongs here

Notebooks, training and evaluation code, preprocessing scripts, model artifacts, per-run
metrics and plots.

## What does NOT belong here

- Specifications and decisions → `../docs/`
- Application code → `../dev/`
- Cross-model consolidated comparisons → `../experiments/`

> The distinction between `ml/*/outputs/` and `experiments/`: `outputs/` holds results for
> **one model**. `experiments/` holds comparisons **across models** — the face-only vs
> text-only vs face+text ablation lives there.
